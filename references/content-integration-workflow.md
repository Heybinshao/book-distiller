# 批量内容整合工作流

> 从大量源文件（如 643 本书的蒸馏拆解）整合为结构化知识手册的完整流程。

## 适用场景

- 书籍拆解 → 主题化知识手册
- 博客文章 → 分类知识库
- 会议记录 → 部门知识手册
- 任何「大量零散文件 → 少量结构化章节」的整合任务

## 工作流程

### Phase 1: 分类

用 `execute_code` 脚本将源文件分入 15-20 个主题：

```python
# 关键词匹配分类
theme_map = {
    "主题A": ["关键词1", "关键词2", ...],
    "主题B": ["关键词3", "关键词4", ...],
    ...
}

for book_name in all_books:
    for theme, keywords in theme_map.items():
        for kw in keywords:
            if kw in book_name:
                categorized[theme].append(book_name)
                break
```

**陷阱**：
- 分类后检查「其他」类——如果超过 50 本，说明分类不够细
- 同一本书只能分入一个主题（取第一个匹配的）
- 分类结果保存为临时文件供子 agent 使用

### Phase 2: 并行整合

用 `delegate_task` 批量处理，每批 3 个子 agent（并发上限）：

```python
delegate_task(tasks=[
    {"goal": "读取主题A的书籍，整合为知识手册章节...", "role": "leaf", "toolsets": ["file"]},
    {"goal": "读取主题B的书籍，整合为知识手册章节...", "role": "leaf", "toolsets": ["file"]},
    {"goal": "读取主题C的书籍，整合为知识手册章节...", "role": "leaf", "toolsets": ["file"]},
])
```

**每个子 agent 的任务描述必须包含：**
1. 书籍文件目录路径
2. 完整书单（文件名列表）
3. 输出路径
4. 整合要求（按逻辑组织，不是逐书摘要；标注来源；保留关键数字/公式/框架）
5. 第一行标题格式

**用户明确要求**：「不能节省篇幅，不能偷懒」——不要在任务描述中说「精简」或「控制篇幅」。

### Phase 3: 质量检查

所有子 agent 完成后：

```bash
# 检查文件大小
ls -lh 输出目录/*.md

# 检查文件数量
ls 输出目录/*.md | wc -l
```

**检查项：**
1. 文件数量 = 主题数量
2. 文件大小均匀（最大/最小比 < 3x）
3. 没有空文件或极小文件（< 5KB）

### Phase 4: 修复

**主题重叠**：在重叠章节开头添加交叉引用
```markdown
> 💡 完整内容见 [[另一章]]。本章聚焦本主题的特定方面。
```

**缺失主题**：为遗漏的源文件创建新章节

**过大主题**：拆分为多个独立文件

**过小主题**：合并到相关主题或扩充内容

### Phase 5: 建 MOC

创建 `00｜MOC名称MOC.md`，包含：

```markdown
# 00｜MOC名称MOC

> 描述文字。

---

## 导读

| 章节 | 核心问题 | 融合书籍数 |
|:-----|:---------|:----------:|
| [[01｜章节名]] | 这个问题的答案 | 36 |
| [[02｜章节名]] | 那个问题的答案 | 43 |
...

---

## 学习路线

按场景推荐阅读顺序：

**想提升X**：[[01]] → [[03]] → [[05]]
**想提升Y**：[[02]] → [[04]] → [[06]]

---

## 数据来源

- **原始文件**：N 本（`01｜原始/`）
- **蒸馏拆解**：N 份（`02｜拆解/`）
- **本整合手册**：M 个主题章节

---

> 共 M 章 · 约 XKB · 整合自 N 本书 · 最后更新：YYYY-MM-DD
```

## 已知陷阱

1. **MOC 必须在所有章节完成后再建/更新** — 子 agent 还在创建新章节时建 MOC，会漏掉后来的章节
2. **不要让子 agent「节省篇幅」** — 用户明确要求不偷懒
3. **「其他」主题不超过 30 本** — 否则必须拆分
4. **文件命名必须与 MOC 链接一致** — 先创建文件，再用实际文件名写 MOC
5. **交叉引用用 Obsidian `[[]]` 格式** — 不用 Markdown `[text](path)` 格式
