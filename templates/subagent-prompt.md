# Subagent 拆书 Prompt 模板

> book-distiller 拆解时，每个 subagent 的完整 prompt。
> 复制后替换占位符：`{工作目录}` `{书名}` `{输出目录}` `{干净书名}`（共 4 个，全部显式替换，禁止原样下发）。其中 `{干净书名}` 由主 agent 统一规范化，与 `{书名}` 通常相同——若输入文件已是干净名，两者填同一个值。

---

## 模板正文

```
你是拆书执行者。输入文件 {工作目录}/{书名}.md 已由 pandoc 转换并清理格式，直接通读全文（可分段读，必须读完 100%）。

【重要：读取文件方式】⚠️ 注意：read_file 工具对「中文内容为主、超过约1KB的文件」会误判为 binary 并拒绝读取（"Binary file - cannot display as text"）——这是工具缺陷，文件本身完全正常。**因此必须用 terminal 执行 python 分段读取全文，不要用 read_file 读这个大文件**。示例读取命令：
python3 -c "
with open('{工作目录}/{书名}.md', encoding='utf-8') as f:
    content = f.read()
lines = content.split('\n')
print(len(lines))
"
然后用 python 分段 print 完整内容（如每段 300-500 行，多次执行确保读完 100%）。可用 write_file 写一个小的 python 脚本再运行，方便分段翻页。

提取要求（全部都要）：
1. 核心命题：一句话
2. 关键概念/心智模型：书中每个独立概念单独成段，格式：**定义** / **机制** / **案例**（保留书中具体细节）/ **启示**
3. 案例：保留细节，不转述精简
4. 金句：原话保留 + 标注章节位置
5. 反模式清单：表格 | 反模式 | 危害 | 书中建议 |
6. 批判性审视：表格 | 书中观点 | 质疑 | 我的看法 |
7. 行动清单：读完可做的具体行动
8. 一句话总结

铁律：完整 > 原话 > 结构 > 篇幅。不合并概念、不省略案例、不精简金句、不概括代替原话、不只写结论不写论证。宁可长不要漏，100% 通读到位产出自然充分，不要为凑篇幅注水。

【重构而非照搬】输出是结构化重构（定义/机制/案例/启示四段式归纳），不是大段复制原文。如果输出接近原文篇幅（>80%），说明你在照搬——每个概念要重组成自己的话，只保留书中原话金句和案例细节。

输出格式：
# {书名} - 完整拆解
> [一句话核心命题]
---
## [主题1]
### [概念1]
**定义**：...

**机制**：...

**案例**：...

**启示**：...
（多个主题/概念）
---
## 金句集锦
> "[原话]" — 第X章

> "[原话2]" — 第X章
---
## 反模式清单
| 反模式 | 危害 | 书中建议 |
---
## 批判性审视
| 书中观点 | 质疑 | 我的看法 |
---
## 行动清单
1. ...
---
## 一句话总结

【空行规范——必须遵守，否则渲染挤在一起】
- 每条金句之间**必须空行**（`> "..."` 与下一条 `> "..."` 之间留空行，否则 Obsidian 会合并成一个引用块）
- **定义/机制/案例/启示 各自独立成段**，之间必须空行
- 标题（# / ## / ###）后紧跟内容时，标题后空一行

【分组编号规范——行动清单若按视角/主题分组】
- 每组列表**各自从 1 开始编号**（如「员工视角 1-12」「老板视角 1-18」「通用 1-2」）
- 不要跨组连续编号（13、31 续下去会让列表被粗体标题割断、渲染易错乱）

用 write_file 写入 {输出目录}/{干净书名}-完整拆解.md（{干净书名} 由主 agent 统一规范化，文件名必须与输入一致，禁止自行简化/改名）。⚠️ **完整拆解文档禁止一次写入**——必须按下方「分段写入规范」操作：首段 write_file ≤5KB，后续段落用独占命名临时脚本 python3 追加。
完成后报告：文件大小、提取概念数、金句数。
```

## 使用说明

- **单本拆解**：复制模板，填占位符，作为 subagent 的 goal+context。
- **批量拆解**：每本一个 subagent，一次 5 个并行（`delegate_task`）——实战验证 5 并发是 524 率与吞吐的最优平衡点；8 并发时 524 失败率飙升到 60%+。
- **铁律行不要删**（「完整 > 原话 > 结构 > 篇幅」「不合并/不省略/不精简」「100% 通读」「不要为凑篇幅注水」）——它们是输出密度的关键，实战产出 84-188KB/本；删了会退回 17KB 的浓缩版。
- **文件名必须与输入一致**——subagent 不得自行简化书名（历史教训：自行简化导致 642 个文件对不上，需逐个重命名修复）。
- **完成后必须报告**：文件大小 / 概念数 / 金句数——用于父 agent 质量检查（结构五件套：金句集锦、反模式清单、批判性审视、行动清单、一句话总结）。

## 分段写入规范（防 HTTP 524 网关超时——622 本实战必用）

单次 API 调用生成超过 120s 会被 Cloudflare 掐断（HTTP 524），15KB+ 文档一次性生成必踩。必须分 3-4 段写入：

1. 第一次用 write_file 写入文档的**第一部分**（核心命题 + 前几个主题，约 5KB）
2. 之后每段：用 write_file 把下一段内容写成临时脚本，**文件名必须独占**：`/tmp/append_{书名前3字}_{段号}.py`（如 `/tmp/append_怪诞_p2.py`）——并行批次里共享同名会被兄弟任务覆盖导致内容污染（实战多次踩坑）。脚本内容格式：`# -*- coding: utf-8 -*-` + `part = """..."""` + `open('{输出路径}','a',encoding='utf-8').write(part)`（`{输出路径}` = `{输出目录}/{干净书名}-完整拆解.md` 的完整路径），再用 terminal 执行 `python3 {脚本路径}`
   - ⚠️ **禁止用 heredoc**（`python3 << 'EOF'`）——会被网关安全扫描误拦（hardline blocklist 误报）
   - ⚠️ write_file 写长内容时尾部闭合语句可能被截断，发现 SyntaxError 用 patch 补齐后重跑
3. 每段控制在 5-12KB 以内；金句集锦/反模式清单/批判性审视/行动清单/一句话总结可各作一段追加
4. 若某次调用仍报 524，把段落再切小重试，不要放弃整份重写
5. 全部追加完成后，用 python 校验五件套标题是否都在、结尾是否完整

## 半成品补尾机制

如果 subagent 超时/触顶只写了概念部分（缺五件套），不要整本重拆——派一个轻量补尾任务：
1. 读已有半成品判断概念写到哪
2. 若概念未完 → 先续写缺失概念
3. 再补五件套（金句集锦 12-15 条 / 反模式清单 8 行表 / 批判性审视 5 行表 / 行动清单 8 条 / 一句话总结）
4. 补尾任务单次生成 ≤4KB，比整本重拆省 70% 时间和 token

## 变体

- **拆解前校验**：转换后先核对书名核心词是否在正文出现（0 次 = 源文件装错书，如「麦肯锡图表工作法.epub」实为《高频交易员》）。校验不通过先报告，不要闷头拆。622 本实战发现 3 本装错书。
- **繁体书**：转换后用 opencc 转简体再拆（`opencc -c t2s -i input.md -o output.md`）。
- **同书重复检测**：批量清单中可能出现同一本书的多个文件名（如「清单革命.md」和「清单革命（新版）.md」指向同一个 md 文件）。用 MD5 对比源文件，相同则去重只拆一份。
- **文学作品适配**：小说/散文/诗集等非方法类书籍，按叙事结构与主题提炼替代八项提取中的方法论部分，其余五件套照常。
- **章节标题格式**：不带序号前缀（写「主题名」而非「一、主题名」）；五件套标题统一为 `##` 二级（不要写成 `#` 一级或带中文序号）——否则父 agent 质检脚本会漏检。
