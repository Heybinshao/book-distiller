# 内容整合 subagent 作业简报（模板，父 agent 分发任务时原文使用）

> 使用方式：复制本文件到工作台 `SUBAGENT_BRIEF.md`，子代理任务指令里只发「读简报 + 本任务差异参数」。
> 【】内为父 agent 按项目替换的占位符。

## 你的任务
把分给你的书单（每本一份「原料包」）融合写成 **一个主题章节的 markdown 文件**。这是「融知识体系」，不是逐书摘要合集：把多本书对同一问题的回答组织成连贯论述。

## 文件位置
- 速览索引（书单+命题+概念名）：【index 路径】
- 原料包：【materials 目录】（文件名规律：书名.mat.md）
- 产出：【output 路径】

## 读文件的规矩
- 中文大文件 read_file 可能误报 Binary——一律用 python 读：分次 print 段落，确保 100% 读完原料包正文
- 逐本读完分到的**全部**原料包再动笔或边读边写，禁止只抽样

## 章节结构（必须）
```
# {章节标题}

> 本章融合 N 本书，回答：{核心问题}。{2-3句导语}

## 第一篇：{篇名}
### {小节：跨书同主题的论点聚合}
论述段落（观点+《书名》标注+关键数字/框架名/步骤）
> "金句原话" ——《书名》
...

（2-4 篇，篇内小节 3-6 个）

## 本章实践清单
- 具体可操作的行动（20 条左右，每条标注来源书）

## 来源书目
- 《书名》（列出你书单里的全部书，一本不落；书名以速览索引为准）
```

## 密度铁律（用户红线）
1. **不节省篇幅、不偷懒、不写「篇幅所限」**——宁长勿漏
2. 你的书单里**每一本**都必须在正文留下至少一个可辨认的贡献（论点/框架/案例/金句），并在来源书目出现
3. 跨书共识：合并成一条主张+多书印证（都标书名）；跨书冲突：并置并指出张力，不许抹平
4. 保留具体：数字、公式、框架名、步骤清单、人名案例，禁止虚化成「书中提到一些方法」
5. 不复制原料包原段——重组语言、按逻辑重排，金句可原样引用

## 长度基准（下限，非目标；一律指 Unicode 字符数，用 python len() 数，不是字节数——中文 UTF-8 每字 3 字节，别把字节数当达标）
- ≤20 本：≥2 万字符；21-40 本：≥3.5 万字符；≥41 本：≥5 万字符；A/B 部分章：≥4 万字符

## 时间策略（必须执行）
- 读料与写作**穿插**：每读完 10-15 本就先写已成型的部分，不要全部读完才动笔
- 收尾结构（实践清单+来源书目）**尽早写上**，之后再补织入细节

## 分段写入（防超时，必须执行）
- 第一次 write_file 只写章头+第一篇前半（≤5KB）
- 之后每段用 python 追加：脚本名独占 /tmp/append_{你的章节号}_{序号}.py，内容 part="""...""" + open(路径,'a',encoding='utf-8') 写入，python3 执行
- 禁止 heredoc（python3 << 'EOF' 会被拦）
- 每追加 2-3 段后 wc -c 校验文件在增长
- 最后读回文件尾部确认结尾完整（来源书目在最后）

## 断点续写（开工第一件事）
1. 先 ls 你的产出路径。文件不存在 → 正常从零写。
2. 文件已存在且尾部**没有**「来源书目」完结段 → 这是上次中断的半成品：读回最后 2000 字弄清写到哪，从断点继续追加，**不推倒重写**；续写前核对最后一段，避免重复内容。
3. 文件已存在且结尾完整 → 不重写，只做核对（书单覆盖、字符数），缺什么补什么，然后直接交报告。

## 完成标准
- 来源书目书数 == 你书单书数（自查数字并写进报告）
- 正文无「篇幅所限」「等等」式偷懒收尾
- 报告：产出路径、字符数（Unicode）、篇/节数、覆盖书数
