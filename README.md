# 📖 书籍榨干器（book-distiller） ![版本](https://img.shields.io/badge/版本-v2.0.0-blue)

> 把你的 epub/pdf/md 丢给 AI，自动拆出核心知识。**不需要任何技术背景。**

---

## ⚠️ 成本提示（请先读这个）

**本 Skill 采取「通读全文再拆书」的方式**：AI 会 100% 通读整本书（分段落读完，不跳页、不扫读），再逐概念提取。

这意味着 **token 消耗比摘要类工具高**——这是拆解质量的来源：

- 拆解质量的核心是「完整 > 原话 > 结构 > 篇幅」——宁可长，不要漏
- 每本书要求 100% 通读 + 保留书中原话金句 + 不合并概念
- 省 token 的代价是输出退回「浓缩版摘要」，那就失去「榨干」的意义了

**成本高低取决于你用的模型**：

- 低成本模型（如 DeepSeek）：拆一本成本很低，放心用
- 高端模型（Claude / GPT）：先拆一本试试，掂量成本后再决定是否批量

**实战数据参考**：622 本批量重拆实测，单本产出中位约 41KB（84-188KB 区间），执行到位时产出天然充分——Skill 不设字数硬指标，防止为凑数注水。

## 这是什么

一个 AI 拆书 Skill。你提供文件，它自动完成：

```
epub/pdf/md → 命名规范化 → 格式转换 → 筛选四查 → 并行拆解 → 质量检查 → 五类归档 → 结果报告
```

输出的拆解文档包含：核心命题、关键概念、金句、案例、反模式、批判性审视、行动清单、一句话总结。

### v2.0 核心特性（622 本批量实战验证）

- **筛选四查（分发 subagent 前必做）**：书名关键词校验（防装错书）→ MD5 同书去重 → 非文字书判定（漫画/绘本/摄影集不拆）→ 双目录覆盖检查
- **五类归档**：源文件按结果分类——`已拆解/` `跳过-非文字书/` `重复-未拆/` `异常-待确认/` `失败-待重试/`，每本书不管什么结局都有明确去处
- **断点续跑**：worklist/progress 双账本记录进度，中断后无缝接上；失败的书自动重试，连续 2 次失败暂停等你决策
- **分段写入防超时**：大文档分 3-4 段写入，独占命名临时脚本追加，规避 Cloudflare 524 网关掐断
- **双维度结果报告**：拆解产物路径+质检结果 + 源文件去向，单本批量都有完整交代

## 建议操作（推荐用法）

**适合拆什么书：**
- ✅ 工具书 / 方法论 / 思维模型类（信息密度高，拆完即用）
- ✅ 你打算精读、但担心读过就忘的书
- ✅ 需要快速检索知识点、不想重翻原书的书

**不建议拆什么书：**
- ❌ 小说、散文、传记（叙事类默认跳过；你点名要拆时走「文学作品适配」模式）
- ❌ 漫画 / 绘本 / 摄影集（纯文字提取后没有可蒸馏的知识结构，Skill 会自动拦下并问你）
- ❌ 工具手册/API 文档（直接查官网更好）

**使用节奏建议：**
- 单本精拆：一次拆一本，读完拆解文档再决定要不要深挖原书
- 批量拆：整个文件夹一次丢进去（每批 5 本并行——622 本实测的最优并发），支持「弄完这批暂停」随时中断续跑
- 拆完归档：拆解产物先进收集箱，确认质量后归档到知识库正式位置

## 前置条件

需要安装两个工具（环境检测会自动检查，缺哪个会提示你装）：

| 工具 | 用途 | macOS | Windows |
|------|------|-------|---------|
| pandoc | epub/pdf→md 转换 | `brew install pandoc` | `winget install pandoc` |
| Python 3 | 格式清理 | `brew install python` | `winget install python` |

可选：`opencc`（繁体书转简体）、`calibre`（mobi/azw3 转 epub）、`pdftotext`（pdf 转换备选）。

## 提示词示例

对你的 AI 编程助手说一句话即可。**单本：**

> 「拆解这本书，文件在 /Users/xxx/Downloads/书名.epub」

**批量（文件夹）：**

> 「帮我拆解这个文件夹，路径在 /Users/xxx/Downloads/待拆解」

**常用变体：**

| 你想做什么 | 这样说 |
|-----------|--------|
| 快速拆解（只要重点） | 「**快速拆解**这本书，只要重点」 |
| 拆完不要移动原文件 | 「拆解这本书，文件在 xxx.epub，**不要移动文件**」 |
| 拆完覆盖旧版 | 「重新拆解这本书，**直接覆盖**旧的拆解文件」 |
| 指定输出位置 | 「拆解这本书，输出到 /Users/xxx/书籍拆解」 |
| 繁体书 | 「拆解这本书，文件在 xxx.epub，**先转简体**再拆」 |

AI 会自动跑完全流程。中途发现异常（疑似装错书、疑似漫画、目标文件已存在）会**停下来问你**，不会闷头干；全部完成后给你一份完整的结果报告，并询问是否清理工作目录。

## 文件处理流程

```
原文件（epub/pdf/md）
   │ ① 命名规范化（提取干净书名，保留系列号；>25 字的超长宣传语会问你）
   ▼
01｜书籍原文/{干净书名}.md          ← 格式转换 + 清理
   │ ② 筛选四查（全部在派发拆解任务之前完成）
   │    ├ 书名关键词校验（防装错书）
   │    ├ MD5 同书去重
   │    ├ 非文字书判定（漫画/摄影集）
   │    └ 覆盖检查（原文+拆解两个目录都查）
   ▼
02｜蒸馏拆解/{干净书名}-完整拆解.md  ← 每 book 一个 subagent 100% 通读
   │ ③ 质量检查（五件套齐全性 + 原文比例 <80% 防照搬）
   ▼
源文件按结果五类归档：
   ✅ 已拆解/  🚫 跳过-非文字书/  🔁 重复-未拆/
   ⚠️ 异常-待确认/  ❌ 失败-待重试/
```

**命名规范**：原文件名可能很长（副标题/括号/作者/英文对照），Skill 自动提取「干净书名」作为基准名（保留系列号，如重来2/好好说话2）。无冒号分隔的超长宣传语（如「职场实用写作课涵盖所有…套装4册」）会取核心短名并**先问你**。同名文件已存在时**询问是否覆盖**，绝不自动创建副本。

## 批量拆解（622 本实战沉淀）

大批量时的内置保障：

| 机制 | 说明 |
|------|------|
| 5 并发最优 | 实测 8 并发时 524 失败率飙升到 60%+，5 是吞吐与稳定性的平衡点 |
| 分段写入 | 首段 ≤5KB + 独占命名临时脚本追加，防单次生成超时被网关掐断 |
| 断点续跑 | worklist + progress 双账本，「继续」从断点接上，不重复已拆的书 |
| 失败自愈 | 无产物→自动重试；缺五件套→轻量补尾（省 70% 时间）；连续 2 次失败暂停问你 |
| 抽查机制 | 每 10 本随机深读 1 本对照原文抽查内容深度 |

## 文件支持

| 格式 | 处理方式 |
|------|---------|
| epub / pdf / md | 直接支持（md 跳过转换，但同样过筛选四查和五类归档） |
| docx / html / fb2 / odt / rtf / txt | pandoc 直接转换 |
| mobi / azw3 | 需先装 calibre 转 epub（未装会提示你） |
| 其他 | 明确告知不支持，建议转 epub 后重试 |

## 拆解文档结构

每本书输出一份标准结构的拆解：

```markdown
# 书名 - 完整拆解
> 一句话核心命题
## 主题章节（每个概念：定义/机制/案例/启示）
## 金句集锦（原话 + 章节位置）
## 反模式清单
## 批判性审视
## 行动清单
## 一句话总结
```

**为什么是这几个版块？** 拆解的目标是「读完拆解 = 带走这本书 80% 的价值」，每个版块对应一个「带走什么」：

| 版块 | 回答什么问题 | 为什么必须有它 |
|------|-------------|---------------|
| 核心命题 | 这本书到底在说什么？ | 30 秒判断要不要深读；没有它，拆解就是一堆散件 |
| 主题章节 · 概念四段式 | 书里有哪些独立概念？怎么运作？ | 把论证拆成可检索的知识点，不合并、不省略 |
| 金句集锦 | 哪些原话值得带走？ | 原话不转述——转述必失真。金句是全书最浓缩的表达 |
| 反模式清单 | 作者反对什么？ | 「不要做什么」比「要做什么」更防坑 |
| 批判性审视 | 这本书哪里可疑？ | 拆解不是背书，留一块「质疑区」防止被一本书带偏 |
| 行动清单 | 读完我能具体做什么？ | 知识不落地等于白读，给可执行动作 |
| 一句话总结 | 全书浓缩成一句话？ | 最小记忆单元，忘了细节再回来看对应章节 |

**为什么每个概念要四段式（定义/机制/案例/启示）？** 一个知识点能被用起来，必须同时回答四个问题：它是什么、怎么运作、凭什么信、跟我什么关系。缺任何一段，这个概念就只剩一半。

## 配置

复制 `config.example.json` 为 `config.json`，修改 `output_path` 指向你的输出目录（不存在会自动创建）：

```json
{
  "output_path": "/你的输出目录/书籍拆解",
  "use_subdirs": true,
  "original_subdir": "01｜书籍原文",
  "distilled_subdir": "02｜蒸馏拆解"
}
```

首次使用时 AI 会展示默认路径并询问你确认，之后直接沿用配置不再重复问。
