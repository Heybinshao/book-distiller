# 📖 书籍榨干器（book-distiller）

> 把你的 epub/pdf/md 丢给 AI，自动拆出核心知识。**不需要任何技术背景。**

---

## ⚠️ 成本提示（请先读这个）

**本 Skill 采取「通读全文再拆书」的方式**：AI 会 100% 通读整本书（分段落读完，不跳页、不扫读），再逐概念提取。

这意味着 **token 消耗比摘要类工具高**——这是拆解质量的来源：

- 拆解质量的核心是「完整 > 原话 > 结构 > 篇幅」——宁可长，不要漏
- 每本书要求 100% 通读 + 保留书中原话金句 + 不合并概念
- 省 token 的代价是输出退回「浓缩版摘要」（15-30KB），那就失去「榨干」的意义了

**成本高低取决于你用的模型**：

- 低成本模型（如 DeepSeek）：拆一本成本很低，放心用
- 高端模型（Claude / GPT）：先拆一本试试，掂量成本后再决定是否批量

输出物：一篇 80-190KB 的完整拆解文档（概念/金句/案例/反模式/行动清单）。

---

## 这是什么

一个 AI 拆书 Skill。你提供文件，它自动完成：

```
epub/pdf/md 文件 → 命名规范化 → 格式转换 → 书名校验 → 覆盖检查 → 通读提取 → 结构化拆解文档
```

输出的拆解文档包含：核心命题、关键概念、金句、案例、反模式、批判性审视、行动清单、一句话总结。

---

## 建议操作（推荐用法）

**适合拆什么书：**
- ✅ 工具书 / 方法论 / 思维模型类（信息密度高，拆完即用）
- ✅ 你打算精读、但担心读过就忘的书
- ✅ 需要快速检索知识点、不想重翻原书的书

**不建议拆什么书：**
- ❌ 小说、散文、传记（叙事类拆解价值低，会丢掉文字的美感）
- ❌ 工具手册/API 文档（直接查官网更好）
- ❌ token 预算紧张时的大部头（先拆目录和关键章节）

**使用节奏建议：**
- 单本精拆：一次拆一本，读完拆解文档再决定要不要深挖原书
- 批量拆：把「待拆解」文件夹一次丢进去（每批 3 本并行），适合集中处理积压书库
- 拆完归档：拆解产物先进「收集箱」，确认质量后归档到自己的知识库正式位置；`01｜书籍原文` 的转换文件可留可删（由你自己决定，不强制清理）

## 前置条件

需要安装两个工具（环境检测会自动检查，缺哪个会提示你装）：

| 工具 | 用途 | macOS | Windows |
|------|------|-------|---------|
| pandoc | epub/pdf→md 转换 | `brew install pandoc` | `winget install pandoc` |
| Python 3 | 格式清理 | `brew install python` | `winget install python` |

可选：`opencc`（繁体书转简体）、`calibre`（mobi/azw3 转 epub）。

## 提示词示例

对你的 AI 编程助手说一句话即可。**单本：**

> 「拆解这本书，文件在 /Users/xxx/Downloads/书名.epub」

**批量（文件夹）：**

> 「帮我拆解这个文件夹，路径在 /Users/xxx/Downloads/待拆解」

**常用变体：**

| 你想做什么 | 这样说 |
|-----------|--------|
| 拆完不要移动原文件 | 「拆解这本书，文件在 xxx.epub，**不要移动文件**」 |
| 拆完覆盖旧版 | 「重新拆解这本书，**直接覆盖**旧的拆解文件」 |
| 指定输出位置 | 「拆解这本书，输出到 /Users/xxx/书籍拆解」 |
| 繁体书 | 「拆解这本书，文件在 xxx.epub，**先转简体**再拆」 |

AI 会自动跑完：环境检测 → 命名规范化 → 格式转换 → 书名校验 → 覆盖检查 → 通读提取 → 质量检查 → 移动源文件。中途发现异常（文件名疑似装错书、目标文件已存在）会**停下来问你**，不会闷头干。

## 文件支持

| 格式 | 处理方式 |
|------|---------|
| epub / pdf / md | 直接支持（md 跳过转换） |
| docx / html / fb2 / odt / rtf / txt | pandoc 直接转换 |
| mobi / azw3 | 需先装 calibre 转 epub（未装会提示你） |
| 其他 | 明确告知不支持，建议转 epub 后重试 |

## 文件处理流程

```
原文件（epub/pdf/md）
   │ ① 命名规范化（clean_book_title 提取干净书名，保留系列号）
   ▼
01｜书籍原文/{干净书名}.md          ← pandoc 转换 + 格式清理
   │ ② 书名关键词校验（防装错书，0 次出现会问你）
   ▼
02｜蒸馏拆解/{干净书名}-完整拆解.md  ← 通读提取，80-190KB 完整拆解
   │ ③ 覆盖检查（同名文件先问你是否覆盖）
   ▼
原文件 → 已拆解/（或同目录已拆解/）   ← 移动源文件，避免重复处理
```

**命名规范**：原文件名可能很长（副标题/括号/作者/英文对照），Skill 自动提取「干净书名」作为基准名（保留系列号，如重来2/好好说话2）。源文件是否重命名由你决定（可选），**拆解文件命名一律用干净书名**：`干净书名-完整拆解.md`。同名文件已存在时**询问是否覆盖**，绝不自动创建副本。

## 拆解文档结构

每本书输出一份标准结构的拆解：

```markdown
# 书名 - 完整拆解
> 一句话核心命题
## 主题章节（每个概念：定义/机制/案例/启示）
## 金句集锦（原话 + 章节位置）
## 反模式清单
## 批判性审视
## 行动清单
## 一句话总结
```

**为什么是这几个版块？** 拆解的目标是「读完拆解 = 带走这本书 80% 的价值」，每个版块对应一个「带走什么」：

| 版块 | 回答什么问题 | 为什么必须有它 |
|------|-------------|---------------|
| 核心命题 | 这本书到底在说什么？ | 30 秒判断要不要深读；没有它，拆解就是一堆散件 |
| 主题章节 · 概念四段式 | 书里有哪些独立概念？怎么运作？ | 把论证拆成可检索的知识点，不合并、不省略 |
| 金句集锦 | 哪些原话值得带走？ | 原话不转述——转述必失真。金句是全书最浓缩的表达，引用、复盘都靠它 |
| 反模式清单 | 作者反对什么？ | 「不要做什么」比「要做什么」更防坑。表格对比 反模式→危害→书中建议，踩坑前先扫一眼 |
| 批判性审视 | 这本书哪里可疑？ | 拆解不是背书。再好的书也有单边叙事，留一块「质疑区」防止被一本书带偏 |
| 行动清单 | 读完我能具体做什么？ | 知识不落地等于白读。给可执行动作，让拆解直接改变行为（按视角分组，方便取用） |
| 一句话总结 | 全书浓缩成一句话？ | 最小记忆单元。过段时间靠它一句话回忆全书，忘了细节再回来看对应章节 |

**为什么每个概念要四段式（定义/机制/案例/启示）？** 一个知识点能被用起来，必须同时回答四个问题：它是什么（定义）、它怎么运作（机制）、凭什么信（案例）、跟我什么关系（启示）。缺任何一段，这个概念就只剩一半。

## 文件结构

```
book-distiller/
├── SKILL.md                          # 主流程（macOS 默认，含 Windows 指引）
├── config.example.json               # 输出路径配置示例（复制为 config.json 使用）
├── references/
│   ├── extraction-framework.md       # 概念识别方法论
│   ├── content-integration-workflow.md  # 批量整合成知识手册
│   └── windows-adaptation.md         # Windows 环境适配
├── templates/
│   └── subagent-prompt.md            # subagent 拆书 prompt 模板（批量拆解必用）
└── scripts/
    ├── clean_md.py                   # 格式清理脚本
    └── quality_check.py              # 拆解质量检查脚本
```

## 配置

复制 `config.example.json` 为 `config.json`，修改 `output_path` 指向你的输出目录（不存在会自动创建）：

```json
{
  "output_path": "/你的输出目录/书籍拆解",
  "use_subdirs": true,
  "original_subdir": "01｜书籍原文",
  "distilled_subdir": "02｜蒸馏拆解"
}
```
